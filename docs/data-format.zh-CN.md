# 数据格式与组织

[使用手册](user-guide.zh-CN.md) · [图解教程](quick-start.zh-CN.md)

## 原始采集

一份采集对应一个 TXT 或 CSV 文件。每行一个按时间顺序排列的采样点，各级码字模式每列对应一级；最终输出码字模式每行只有一个最终整数码字。建议使用无表头、无时间戳和序号列的纯数值文件。

| 模式 | 填写内容 | 关键约束 |
| --- | --- | --- |
| 各级码字 | 各级位宽、级间增益、输入编码、交织路数 | 列数和 ADC 级数一致，同一目录采用同一规格 |
| 最终输出码字 | 输出位宽 N、无符号或有符号编码、交织路数 | 单列整数；无需各级增益或单独基准文件 |
| 交织采集 | 实际通道数 L 和总输出采样率 | 行顺序为 lane 0 到 L−1 循环，行数应形成完整帧 |

各级的“偏移二进制”需要与对应位宽一致的二进制表示。最终码字的有符号二进制按补码解释，不要把两类编码设置混用。

最终输出位宽范围为 1～32 bit。无符号范围为 0～2^N−1；有符号范围为 −2^(N−1)～2^(N−1)−1。每行可用十进制整数或恰好 N 位二进制字符串。越界、小数、非有限值和不完整帧会被拒绝。

## 预处理后的三个角色

| 当前名称 | 内容 | 旧版兼容名称 |
| --- | --- | --- |
| `inputs` | 输入数据 | `code` |
| `baseline` | 配套基准数据 | `actual` |
| `reference` | 训练目标所依据的参考信号 | `ideal` |

各级码字模式通常有三个目录。最终输出码字模式可能只有 `inputs` 与 `reference`，属于正常情况，不要手工补齐第三个目录。

```text
prepared/
  train_4/
    inputs/
    baseline/
    reference/
    adc_config.json
    raw_testing.json
  raw_test/
    raw_sources.json
```

上图为各级模式的示意；实际分组数、其他输出和目录位置由预处理结果决定。角色文件按末尾采集编号配对。同一角色不能同时出现新、旧两套目录。

## 训练、调参与最终测试

训练选择预处理结果的根目录或 `train_组数`，不要只选 `inputs` 子目录。模型测试选择原始采集或 `raw_test`，不要选择预处理的 `train_组数` / `test_组数` 来替代原始输入。

`raw_test` 可以是原始文件的引用清单，原文件需要保留。用于模型搜索、剪枝或位宽选择的数据参与了方案选择；最终性能结论应在另外保留的测试数据上确认。

## 单音、双音与采样率

信号模式必须与采集一致。双音提示频率使用归一化的 `f/fs`，例如 100 MHz / 1 GHz 填 `0.1`。频谱计算中的采样率填写完整输出序列的总采样率；两路各 700 MS/s 的交织 ADC 填 1.4 GS/s。

当前操作说明以单音、双音采集为范围。其他信号不能仅因文件可导入就视为已受支持，请根据软件检查结果选择适用流程。

## 读取范围

“每组读取行数”控制每份采集读取多少行，0 表示全部，交织数据按完整帧对齐。它不是所有文件合计行数，也不是批大小。训练、测试、剪枝和逐轮频谱具有各自的读取设置。

报告结果时同时记录读取行数、采样率、信号模式、数据来源和划分方法。用前 32768 行得到的结果，仅证明该读取范围内的表现。
