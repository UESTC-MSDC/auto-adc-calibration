# 常见问题与排错

[安装](installation.zh-CN.md) · [快速上手](quick-start.zh-CN.md) · [配置参考](reference.zh-CN.md)

保留错误文本和当前任务，先检查对应输入或设置，再重试相同步骤。

## 1. 安装与启动

| 现象 | 处理 |
| --- | --- |
| 缺少 DLL 或无法启动 | 校验全部分卷，重新完整解压到可写目录，保留 EXE、Worker 和运行库的相对位置 |
| 主界面正常，任务启动失败 | 检查 `KAN Worker.exe`、任务错误文本和输出目录权限 |
| 下载的 ZIP 中没有程序 | 下载 Release 的 Windows x64 附件；仓库快照用于文档和样例 |
| 系统拦截 | 核对官方来源、散列和具体提示，按系统建议处理 |
| 文档中的样例目录不存在 | 从当前仓库下载文档快照，查找 `examples/tutorial/raw/` |

## 2. GPU 与训练设备

<a id="gpu"></a>

有兼容 NVIDIA GPU 时使用 `cuda` 训练。设备未识别时依次检查：

1. 在终端运行 `nvidia-smi`，确认系统能识别显卡与驱动。
2. 在软件设置页检查 CUDA 信息；核对当前驱动与发行包运行库的兼容性。
3. 在 **配置 → 浮点模型 → 模型训练 → 运行设置** 明确选择 `cuda`，启动后检查实际设备。
4. CUDA 状态仍异常时，保存错误文本、GPU 型号及驱动版本再反馈。

`auto` 会根据环境选择设备；看到 CPU 时应先查明原因。无需为已打包程序另装 CUDA 开发工具包。显存不足时将批大小从 256 降至 128 或 64，再按需要减小模型或窗口，并记录修改。

## 3. 数据与自动分集

| 现象 | 处理 |
| --- | --- |
| 文件数或列数异常 | 教程应选 `examples/tutorial/raw/`：20 个 CSV，每个 8192×6；检查表头、时间戳和多余列 |
| 码字越界 | 核对数据来源、编码和各级位宽；教程使用有符号十进制 |
| 设置被锁定 | 选择“重新开始”，修改后重新检查 |
| 未生成 `train_N` 或 `raw_test` | 核对测试比例；0% 时训练角色直接位于结果根目录 |
| 测试编号与教程记录不同 | 软件随机留出完整采集，以当前分集记录为准；20% 应留出 4/20 组 |
| `raw_test` 无法读取文件 | 恢复引用的原始 CSV，或重新建立预处理任务 |
| 单音拟合异常 | 核对信号类型、通道顺序、位宽与名义增益；保持原始码字完整 |

## 4. 训练与测试结果

| 现象 | 处理 |
| --- | --- |
| 训练数据配对失败 | 选择完整 `train_N`；检查编号及 `inputs/baseline/reference`，同一角色只保留一套目录名 |
| 测试提示缺少配方或参照 | 使用完整训练任务内的匹配模型，恢复配套文件 |
| 测试出现训练采集 | 选择本次预处理生成的 `raw_test`，核对留出编号 |
| 损失下降但指标不改善 | 检查采样率、信号模式、读取行数和数据分布，逐组查看频谱 |
| 指标没有达到教程数值 | 核对样例散列和完整设置；随机划分可能不同，实测噪声与误差也不同 |
| 位宽扫描通过但量化未达标 | 确认方案已应用，检查量化训练与最终验收原因 |

教程用低噪声受控仿真突出可校准误差。更高的随机噪声、抖动、温漂或训练与测试条件变化会限制实际改善；不能仅凭训练损失判断校准效果。

## 5. 硬件任务与项目迁移

| 现象 | 处理 |
| --- | --- |
| RTL/ASIC 缺工具或组件 | 核对工具路径、许可与 ASIC 扩展完整自检结果 |
| 任务超时、取消或未收敛 | 保留结果，检查阶段及资源，再恢复兼容任务 |
| 移动项目后找不到数据 | 恢复外部原始文件，检查保存的引用 |
| 两次报告难以比较 | 对齐工艺、时钟、模型接口、输入活动和已运行阶段 |

## 6. 反馈材料

提交软件及 Windows 版本、GPU 型号与驱动、所在页面、复现步骤、预期结果和错误文本。能用样例复现时，附采集编号、数据划分和修改后的参数。

日志与截图先去除凭据、个人路径和私有数据。提交方式见[CONTRIBUTING](../CONTRIBUTING.md)；私密问题按[安全报告说明](../SECURITY.md)处理。
