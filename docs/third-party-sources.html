第三方源码与库替换 / Third-party sources and library replacement

第三方声明 · 组件清单

本页适用于随软件分发的 Qt、PySide6 与 Shiboken 6.9.3。应用使用独立动态库，未修改这些上游组件的源码。第三方源码按其自身许可提供；应用原创源码不在这些附件内。

1. 获取对应源码

在对应软件的 Release 中查找以下源码附件，或使用该页明确列出的复用下载链接。对应源码的组件版本和 SHA-256 应与本页及源码清单一致；复用旧 Release 的同一文件不表示软件版本相同。下载或使用第三方源码无需另行购买本软件授权。

2. 在软件副本中构建与替换

  1. 备份整个软件目录并关闭主程序及 Worker，在单独副本中操作。
  2. 参考源码内的构建说明和 Qt for Windows 构建指南，使用兼容的 Windows x64 MSVC、CMake 与 Ninja 工具链。保持共享库构建；Qt 模块包括 Core、Gui、Widgets、Network、Svg 和 OpenGL，以及对应的 Windows 平台和图像插件。
  3. 若修改 Python 绑定，按 Qt for Python 构建指南 构建 PySide6/Shiboken，保持版本 6.9.3、Windows x64 架构及 CPython 3.12 兼容性。以源码内的构建文件为准。
  4. 将兼容的 Qt DLL 和插件替换到软件副本的 _internal/PySide6/ 相应位置；绑定位于该目录，Shiboken 位于 _internal/shiboken6/。成组替换相关库，保留目录关系，避免混用不兼容的版本、架构或调试/发行构建。
  5. 启动主程序，检查窗口、SVG 图表及一次样例任务。若自行构建的库不兼容，可恢复备份。发行包没有用于禁止兼容 LGPL 库替换的应用签名校验；校验清单用于辨别原始附件，修改后的文件散列自然会不同。

完成检查： 修改后的副本能启动、显示图表并完成一次样例任务；原备份仍可恢复。替换库的兼容性需要自行验证，官方测试记录针对随包上游二进制。

使用者保留 LGPL 所允许的修改、库替换和为调试修改后的库而进行必要逆向分析的权利。软件自身的非商业条款不削减这些权利。

English

Find the matching Qt and PySide6/Shiboken 6.9.3 source archives in the application's Release assets or through the reuse links explicitly listed in its release notes. Verify component versions and SHA-256 against the source manifest. A reused file hosted in an earlier Release is the same component source, not an indication of the application's version. The archives include upstream build files, are unmodified and match upstream hashes; this project applies no patches to these libraries.

The application uses shared libraries. Back up the complete application, close both executables, build compatible Windows x64 release libraries using the upstream instructions, and replace the corresponding DLLs/plugins under _internal/PySide6/ and bindings under _internal/shiboken6/. Keep Qt/PySide6/Shiboken versions and the CPython 3.12 ABI compatible. Test the modified copy before further use. LGPL modification, replacement and necessary debugging rights are preserved; the application's own noncommercial terms do not remove those rights.
