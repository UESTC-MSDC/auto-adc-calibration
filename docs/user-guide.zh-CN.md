# 完整使用教程

[首页](../README.zh-CN.md) · [快速上手](quick-start.zh-CN.md) · [配置参考](reference.zh-CN.md) · [排错](troubleshooting.zh-CN.md)

本教程说明如何把样例流程迁移到实际实验，并管理模型、测试与后续优化。首次使用先完成快速上手；参数定义统一见配置参考。

## 1. 建立可复查的实验

分别安排软件目录、项目目录和原始数据目录。原始采集保留只读副本；不同 ADC、采样条件或实验目标使用独立项目或任务。

开始前记录 ADC 结构、编码、通道数、总采样率、信号类型、采集条件及文件来源。每份文件是一组连续采集，每行一个采样点；CSV/TXT 不添加表头、时间戳或序号列。

| 输入情况 | 软件设置 |
| --- | --- |
| 每列为一个 ADC 级的码字 | 各级码字，填写级数、各级位宽和名义级间增益 |
| 每行一个最终 ADC 整码 | 最终输出码字，填写输出位宽和编码 |
| 一个补码码字按位拆成多列 | 各级码字／补码二进制；每列 1 bit，最高位在前 |
| 多路交织 ADC | 同时填写通道数，按通道顺序逐行交织，使用合并输出总采样率 |

具体范围、列顺序与预处理产物见[输入与数据目录](reference.zh-CN.md#data)。

## 2. 自动分集与预处理

将本次同类原始采集放在一个目录，在 **数据** 页选中它。填写编码与 ADC 参数，设置测试集比例；教程使用 20%。软件按完整采集文件随机留出测试组，训练组和测试组不会共享同一份采集文件。

依次执行 **检查数据 → 开始预处理**。修改已检查设置时先选择 **重新开始**，再检查和执行。若使用自定义列权重，按界面完成初始权重扫描。

20 份采集、20% 测试比例的结果如下：

```text
预处理结果/
├─ train_16/       训练数据及配套配置
├─ test_4/         留出采集的预处理数据
└─ raw_test/       独立原始采集的测试入口
```

训练使用 `train_16`；常规模型测试使用 `raw_test`。入口可能只保存原始文件引用，因此原始数据要与项目一起保留。

已按采集批次或工况保留外部测试数据时，可将测试比例设为 0%，训练数据另行处理。随机文件划分适合入门及同分布评估；跨器件、跨温度或跨批次泛化需要对应的独立采集。

## 3. 训练与独立评估

进入 **配置 → 浮点模型 → 模型训练**，核对训练目录、输入模式、采样率和读取行数。有兼容 NVIDIA GPU 时将 **运行设置 → 计算设备** 设为 `cuda`，并在训练页确认实际设备。

教程配置使用窗口数量 1、隐藏层 2、grid 1、k 2、120 轮和批大小 256，完整设置见[快速上手](quick-start.zh-CN.md)。该样例没有记忆项；自有数据的窗口大小应按其时间相关误差调整。

训练完成后，在 **测试** 页选择同一任务的模型与 `raw_test`，核对单音/双音及读取范围。采样率随模型读取，应与原始采集条件一致。

### 读取报告

| 指标 | 含义 | 比较方式 |
| --- | --- | --- |
| SNDR | 信号相对总体噪声与失真的比值 | 同一采集及计算条件下越高越好 |
| SFDR | 信号相对最大杂散的比值 | 同时查看杂散频点和频谱形态 |
| ENOB | 由 SNDR 换算的有效位数 | 使用报告定义，结合信号条件解释 |
| 训练损失 | 模型拟合训练参考的误差 | 用于观察训练，不替代独立测试 |

教程现在使用 **6→2→1、214 个参数** 的小网络。全部四组独立测试的 SNDR 提升 29.86–29.97 dB，SFDR 提升 33.00–33.43 dB；完整逐组数值、真实界面与频谱见[快速上手](quick-start.zh-CN.md)。

### 区分误差校准和降噪

静态校准针对可重复的转换误差。频谱底部还可能混有码字重建误差和量化误差，不能把所有“底部下降”解释为真实随机噪声减少。教程额外比较了保留输入噪声与后端量化误差的已知参数反演，并用新噪声实现核查噪声传递；模型的输入噪声传递系数约 1.0009。

同一冻结模型在训练组和最终测试组上的平均 SNDR 为 76.04 dB 与 76.11 dB，没有明显训练优势。结构选择使用训练侧验证集，最终四组不参与本轮调参；`best.pt` 按训练损失保存。完整方法与限制见[小模型验证与噪声核查](../examples/tutorial/model-validation.md)。这些结果来自固定幅度、固定器件的教学仿真，迁移到实际实验仍须保留独立采集。

### 比较多个实验

固定数据划分、测试采集、采样率、读取范围和信号模式，仅改变待研究的设置。逐组比较并保留失败或退化结果。参加调参、模型搜索、剪枝验收和位宽选择的数据属于方案选择数据，最终性能报告应使用另外保留的采集。

## 4. 优化模型并衔接硬件流程

| 目标 | 操作顺序 | 保留结果 |
| --- | --- | --- |
| 自动选择结构 | 模型搜索 → 选择模型 → 独立测试 | 搜索条件、候选状态、测试报告 |
| 减小模型 | 模型剪枝 → 查看验收 → 按需剪枝训练 → 复测 | 剪枝前后模型、精度与规模 |
| 准备定点模型 | 位宽扫描 → 应用方案 → 量化训练 → 最终验收 | 位宽方案、量化模型、浮点参照 |
| 检查数字实现 | 兼容模型 → RTL 导出／仿真与综合 | 实际运行阶段的报告与输入条件 |
| 评估目标工艺 | ASIC 环境自检 → 逻辑综合 → 物理实现 → 功耗评估 | 工艺、约束、阶段状态及报告 |

“增益保留 80%”是校准改善的保留目标；连接保留率应查看模型规模结果。位宽扫描得到候选方案，应用后的训练与最终验收仍需完成。

硬件流程从适用模型及完整配套文件开始。RTL 已导出、仿真通过、综合完成、物理验证通过分别记录；工具、模型和约束的要求见[硬件功能参考](reference.zh-CN.md#hardware)。

## 5. 保存、继续与迁移

<a id="backup"></a>

使用 **打开目录** 定位任务，备份以下材料：

| 材料 | 内容 |
| --- | --- |
| 项目与完整任务目录 | 配置、模型、预处理配方、浮点参照、日志与报告 |
| 原始采集 | 训练、验证、测试文件及其用途记录 |
| 实验条件 | 实际软件版本、设备、采样率、行数、模型设置和数据划分 |
| 软件环境 | 对应版本的完整安装目录或发行包 |

继续训练使用匹配任务的 **继续训练** 入口；新对照实验保存为独立任务。模型及配套文件共同构成可恢复结果，仅复制 `best.pt` 可能缺少后续步骤所需材料。

升级时，将新版软件解压到新目录，用项目副本验证数据引用、模型和报告。需要回退时，使用旧版完整软件打开升级前备份。移动项目后检查外部数据引用，确认副本可使用后再清理旧目录。

## 6. 处理异常并反馈

保留错误文本、失败阶段和任务目录，按[常见问题与排错](troubleshooting.zh-CN.md)逐项核对。使用样例复现时记录调整过的参数和分集编号。

反馈包含实际软件版本、Windows 版本、GPU 与驱动、操作步骤、预期结果和错误文本。分享前去除凭据、私有采集和个人路径；文档贡献与报告格式见[CONTRIBUTING](../CONTRIBUTING.md)。
