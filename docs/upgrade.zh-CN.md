# 升级、备份与回退

[安装](installation.zh-CN.md) · [使用手册](user-guide.zh-CN.md)

**目标：** 用项目副本确认新版可用，同时保留能回到旧版的完整材料。

## 1. 先备份三个位置

等待任务完成，或通过软件正常停止；记录未完成任务的状态后关闭软件。

| 备份内容 | 为什么需要 |
| --- | --- |
| 旧版完整软件目录 | 回退时保持 EXE、Worker 和运行库匹配 |
| 项目及完整任务结果 | 保留模型、配置、报告和恢复证据 |
| 项目引用的外部原始数据 | 仅复制项目目录可能漏掉这些文件 |

例如“Pipelined 入门”项目，应同时保留项目目录及 `examples/pipelined/raw-train`、`raw-test`。不要只保存一个模型或结果截图。

## 2. 在副本上验证新版

1. 阅读新版发行说明，将软件完整解压到新的独立目录。
2. 复制待验证项目，用新版打开这份副本。
3. 检查原始数据引用、模型与历史报告是否可访问。
4. 用少量数据完成一次训练或测试，确认需要的流程可用后再安排正式任务。

**完成检查：** 新版软件、项目副本和外部数据均可用。能打开旧项目不代表所有历史检查点都能直接续算，继续任务时仍按兼容性检查处理。

## 3. 处理兼容性差异

- 旧 `code/actual/ideal` 与新 `inputs/baseline/reference` 是两套角色名称；不要在同一数据集混放同一角色的新旧目录。
- 模型及配套配置、参照和任务文件一起保留；恢复检查不通过时按提示查差异。
- ASIC 扩展更新可能改变工具和工艺环境，比较结果时保留原报告条件。

## 4. 必要时回退

关闭新版，使用旧版完整软件打开**升级前的项目备份**。外部原始数据也要可访问；不要把新版已经修改过的项目直接当成旧版备份。

清理旧目录前，确认软件、项目和外部数据之间的引用。软件可以重新下载，用户采集和历史任务未必能重新生成。
