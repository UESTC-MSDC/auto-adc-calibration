故障排查

首页 · 安装 · 使用手册

先记录软件版本、正在进行的操作、完整错误文本和实际运行设备。优先按错误中指出的文件或配置定位；保留原项目和输入数据。

现象 优先检查 建议处理
双击后无法启动 / 缺少 DLL 是否只复制了 EXE、是否在压缩包中运行、附件校验是否正确 重新完整解压同一版本，保留所有资源；根据具体提示处理运行库
GUI 可打开，任务不能启动 Worker 是否完整、目录是否可写、任务错误文本 保留完整包，改用独立可写目录，检查任务日志
CUDA 不可用或实际跑在 CPU 驱动、显卡和软件运行库是否兼容 先用 CPU 确认流程，按该版本运行条件排查 GPU
显存不足 批大小、模型规模、同时运行的任务 降低批大小，例如 256 → 128 → 64；记录条件变化
找不到训练数据 / 配对失败 是否选了数据根目录、编号是否匹配、新旧角色名是否混用 选择正确根目录；修正来源或重新预处理，勿手工拼接不同任务
输入越界或帧不完整 位宽、符号、二进制格式、交织顺序和行数 对照实际 ADC 与文件格式修正，不截断数值掩盖错误
原始测试缺少配方 模型与预处理元数据是否完整 找回对应任务及配方，或按正确数据重建训练流程
设置被锁定 数据检查或扫描已经完成 按界面“重新开始”解除状态，修改后重新检查
损失下降但 SNDR/SFDR 不改善 数据划分、信号类型、频谱设置和指标目标 使用独立原始采集逐组比较，不只看训练损失
不能量化 模型与所选功能是否兼容 按界面兼容性提示选择合适模型
位宽扫描通过，QAT 未达标 扫描方案是否应用、训练与整数验收是否完成 核对方案与来源，查看最终验收；不要把扫描视为最终模型
外部数据移动后续跑失败 项目仍引用原位置，内容校验可能不同 恢复原文件或通过正常入口重新选择，保留旧结果
ASIC 缺组件 / 自检失败 WSL2、扩展版本、仿真运行时和空间 完成对应扩展自检；旧离线包不一定满足当前要求
ASIC 超时 / 取消 / 未收敛 当前阶段、累计时间、资源和失败原因 保留实验结果，按原因调整预算后继续兼容流程
不同报告无法计算改善比例 工艺、时钟、模型、接口或证据是否一致 按软件列出的差异判断可比范围

提交问题时提供什么

  • 软件版本和 Windows 版本；使用 CPU 还是哪款 GPU，相关驱动信息。
  • 发生问题的页面、操作步骤、可重复的最小输入条件。
  • 经过清理的错误文本或截图；区分崩溃、未达标、超时与未执行。

分享日志前检查是否含原始数据、机构内部目录、个人路径、凭据和未公开项目信息。尽量用合成样例复现。授权和使用咨询可联系 644245542@qq.com。
